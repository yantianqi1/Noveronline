# MiroFish-Novel Design

> 这是 `MiroFish` 向小说预测与平行世界推演平台迁移的设计文档。

## 目标

建立一个新仓库，专门承接小说分析与平行世界推演场景，同时最大化保留旧项目里已经验证有效的底层能力。

## 核心设计决策

### 1. 不整仓复制

原因：

- 旧仓库的“引擎”有价值
- 旧仓库的“舆情 / 社交平台产品壳”会成为包袱

所以采用：

- 新仓库
- 新产品定位
- 旧模块按价值迁移

### 2. 先后端、后前端

第一阶段优先把后端能力打通：

- 小说种子上传
- ontology 生成
- 图谱构建
- 角色 / 势力档案生成
- 平行世界配置生成

原因是这几块决定系统是不是“真的懂小说”。

### 3. 存储架构延续旧项目优点

当前继续采用混合存储：

- 文件系统：项目、报告、配置
- Zep：世界图谱
- 后续世界线运行记录：可继续沿用 SQLite 或升级主数据库

### 4. 领域建模转向小说

新的实体与关系，不再优先围绕社交传播，而是围绕：

- 角色
- 阵营 / 组织 / 势力
- 世界规则
- 剧情事件
- 冲突
- 关系弧线
- 人机关系

## 第一阶段交付范围

- 新仓库初始化
- 文档体系建立
- 可复用模块迁移
- 小说专用服务建立
- 基础 API 打通

## 非目标

第一阶段不追求：

- 最终版前端
- 真正的世界线演化引擎
- 沉浸式角色扮演 UI
- 生产级部署方案
