 MiroFish-Novel 地基优化计划                                                                                                                                                                  
                                                                                                                                                                                              
 Context

 问题背景

 MiroFish-Novel 的核心管线目前依赖纯正则提取角色/组织（novel_seed_analyzer.py 的 5 个正则模式），无法可靠识别哪些文字是角色名。用户明确要求：分段后直接调用 LLM 进行角色提取。

 同时，用户要求在四个方向全面优化：
 1. 解决千章级小说并发 LLM 处理时的剧情连续性问题
 2. 世界线影响力传导 — 小人物行为只影响相关人，大势力改变世界格局
 3. Agent 可扩展架构 — 不同类型 Agent 拥有不同数据结构
 4. 前端引导优化 — 让新用户一看就懂

 核心设计决策

 用 LLM 做主力提取，用现有正则做"骨架预扫描"解决并发连续性。

 逻辑：1000章 → 100个文本块 → 并发调LLM。但第20个块不知道前19个块的内容。
 解决方案：先用现有正则做一次快速顺序扫描（几秒完成），生成"骨架时间线"（谁在哪章出现），然后每个 LLM 调用都带上这份骨架作为上下文。这样即使并发，每个块都"知道"全文的角色全景。

 Phase 2: 世界线影响力传导模型

 目标：让演化引擎有"涟漪效应"——小人物行为只影响身边人，大势力决策改变整个世界。

 2.1 新建 influence_propagation.py

 路径: /Users/项目/MiroFish-Novel/backend/app/services/influence_propagation.py

 核心算法：BFS 在关系图上传播影响力

 IMPORTANCE_TIER_WEIGHTS = {
     "protagonist": 1.0,
     "major": 0.7,
     "supporting": 0.4,
     "minor": 0.15,
 }
 RELATION_PROPAGATION_DECAY = 0.5  # 每一跳衰减 50%

 class InfluencePropagationModel:
     def propagate(
         self,
         actor_name: str,
         action_weight: float,
         actor_states: Dict,
         organization_states: Dict,
         relationship_states: List[Dict],
         max_depth: int = 3,  # 用户可自定义：低度演化=1层，高度演化=全部
     ) -> List[Dict]:
         """
         从 actor 出发，通过关系图 BFS 传播影响力。
         influence = base_importance × action_weight × decay^hops
         只有 influence >= 0.1 的实体才会收到状态变更。
         """

 - 从 relationship_states 构建邻接表
 - 从触发者出发 BFS
 - 每一跳 influence × DECAY
 - 返回受影响实体列表，按影响力排序
 - max_depth 参数对应用户提到的"演化强度"：低度=1层，中度=3层，高度=无限
