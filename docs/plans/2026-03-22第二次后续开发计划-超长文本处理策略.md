 超长小说文本并发处理连贯性深度优化方案

 Context

 问题根源

 MiroFish-Novel 的种子提取管线处理 1000 章小说时，100 个分析块需要并发调用 LLM。当前架构存在三个层次的连贯性缺陷：

 1. 第一层：上下文盲区 — 并发提取局部事实时（Stage 4），每个块仅拥有"骨架时间线"（角色名列表）和 2 章重叠上下文，完全没有前序剧情摘要。Block 20 不知道 Block 15 中某角色已死亡。
 2. 第二层：顺序瓶颈 — 故事记忆合并（Stage 5）是 O(n) 顺序操作，100 个块必须逐个合并后才能生成快照，阻塞了后续所有阶段。
 3. 第三层：快照容量不足 — 每个块的前情快照仅 2000 字 + 12 个实体 + 12 条关系。1000 章小说可能有 200+ 角色，大量关键信息被截断丢失。

 设计理念：河流架构（River Flow Architecture）

 你无法在每块都需要完整上游信息的情况下并发处理一条河流。但你可以：先鸟瞰河流画地图（骨架），再沿河流栽路标（锚点），最后让每个分析员带着地图和最近的路标同时工作。

 核心公式：并发安全 = 全局骨架 + 定距锚点 + 自适应快照 + 后合并消歧

 设计原则：LLM 强制驱动

 所有涉及语义理解的步骤强制使用 LLM，不提供离线兜底。理由：
 - 正则/启发式无法理解剧情因果、角色动机、关系微妙变化
 - 既然用户选择运行管线，就应该获得最高质量的分析结果
 - 仅纯数据结构操作（合并、排序、消歧算法）不调用 LLM

 LLM 强制步骤： 锚点生成、块内事实提取、上下文剧情分析、本体生成
 纯算法步骤： 章节指纹（启发式足够）、树状合并、实体消歧、一致性审计

 算法

 def _chapter_fingerprint(self, chapter: Dict[str, Any]) -> str:
     """提取章节剧情指纹：首句(场景设定) + 含最多角色名的句子(核心冲突) + 尾句(悬念)。"""
     sentences = split_sentences(chapter["content"])
     if not sentences:
         return chapter.get("title", "")

     # 首句：场景设定
     opening = sentences[0][:100]

     # 核心句：包含最多角色名的句子（通常是核心冲突所在）
     character_names = set(self._extract_names_from_text(chapter["content"]))
     core = max(sentences[1:-1] or [opening],
                key=lambda s: sum(1 for n in character_names if n in s))[:100]

     # 尾句：章末悬念钩子
     tail = sentences[-1][:100] if len(sentences) > 1 else ""

     parts = [opening]
     if core != opening:
         parts.append(core)
     return "；".join(parts)

 def _chapter_tail_hook(self, chapter: Dict[str, Any]) -> str:
     """提取章末尾钩（最后1-2句），用于桥接下一章。"""
     sentences = split_sentences(chapter["content"])
     return "；".join(sentences[-2:])[:120] if sentences else ""

 class AnchorPointBuilder:
     """在并发提取前生成定距锚点摘要。强制使用 LLM。"""

     MODULE_KEY = "anchor_point_summary"
     DEFAULT_ANCHOR_INTERVAL = 5  # 每 5 个块一个锚点

     def __init__(self, llm_router: Optional[LlmRouter] = None):
         self.llm_router = llm_router or LlmRouter()

     def build(
         self,
         blocks: Sequence[Dict],
         chapters: Sequence[Dict],
         skeleton: Dict,
         anchor_interval: int = DEFAULT_ANCHOR_INTERVAL,
         progress_callback=None,
     ) -> Dict[str, Any]:
         """顺序生成锚点（强制 LLM）。每个锚点继承前一个锚点的世界状态并追加新变化。"""
         chapter_map = {c["chapter_id"]: c for c in chapters}
         fingerprint_map = {s["chapter_id"]: s for s in skeleton.get("chapter_sketches", [])}

         anchors = []
         cumulative_state = self._empty_world_state()

         for i in range(0, len(blocks), anchor_interval):
             anchor_blocks = blocks[i:i + anchor_interval]
             anchor_chapters = self._gather_chapters(anchor_blocks, chapter_map)
             anchor_fingerprints = self._gather_fingerprints(anchor_blocks, fingerprint_map)

             anchor = self._build_anchor_with_llm(
                 anchor_blocks, anchor_chapters, anchor_fingerprints,
                 cumulative_state, skeleton
             )

             # 累积更新世界状态
             cumulative_state = self._merge_anchor_into_state(cumulative_state, anchor)
             anchors.append(anchor)

             if progress_callback:
                 progress_callback("complete", {"anchor_id": anchor["anchor_id"]})

         return {"anchor_count": len(anchors), "anchors": anchors}

 模块 3：树状并行合并

 目标

 将故事记忆合并从 O(n) 顺序降为 O(log₂n) 轮次的并行操作。

 修改文件

 backend/app/services/story_memory_builder.py — 新增 build_tree 方法

 核心思想

 Round 0 (100 packets):
   [P1] [P2] [P3] [P4] ... [P99] [P100]

 Round 1 (50 merges, parallel):
   [P1+P2] [P3+P4] [P5+P6] ... [P99+P100]

 Round 2 (25 merges, parallel):
   [P1-4] [P5-8] [P9-12] ... [P97-100]

 Round 3 (13 merges):
   [P1-8] [P9-16] ... [P97-100]

 ...

 Round 7 (1 merge):
   [P1-100] ← 全局故事记忆

 重要：树状合并仅用于加速全局记忆构建。快照生成仍然使用顺序前缀累积方式。

 算法

 def build_tree(self, packets: Sequence[Dict[str, Any]], max_workers: int = 10) -> Dict[str, Any]:
     """树状并行合并。每一轮将相邻对合并，直到只剩一个全局记忆。"""
     ordered = sorted(packets, key=lambda p: p["block_id"])

     # 初始化：每个 packet 转为一个 mini memory
     segments = [self._packet_to_segment(p) for p in ordered]

     # 树状合并 → 仅产出全局记忆
     while len(segments) > 1:
         next_segments = []
         pairs = []
         for i in range(0, len(segments), 2):
             if i + 1 < len(segments):
                 pairs.append((segments[i], segments[i + 1]))
             else:
                 next_segments.append(segments[i])  # 奇数个，最后一个直接晋级

         # 并行合并所有配对
         with ThreadPoolExecutor(max_workers=min(max_workers, len(pairs))) as executor:
             merged = list(executor.map(
                 lambda pair: self._merge_two_segments(pair[0], pair[1]),
                 pairs
             ))

         next_segments = merged + next_segments
         segments = next_segments

     global_memory = segments[0]

     # ★ 关键：快照使用顺序前缀累积生成，不从全局记忆切片
     # 这样保证每个块的快照只包含"此块之前"的信息，不会泄漏未来
     snapshots = self._generate_snapshots_sequential(ordered)

     return {"story_memory": global_memory, "snapshots": snapshots}

 def _generate_snapshots_sequential(self, ordered_packets: List) -> List:
     """顺序前缀累积生成快照 — 与原 build() 方法相同的逻辑。

     ★ 为什么不从全局记忆切片：
     全局记忆的 entity_registry 中，后块的 summary 会覆盖前块的 summary
     (story_memory_builder.py line 113: if entity.get("summary"): record["summary"] = entity["summary"])。
     如果从全局记忆切片给前面的块，前面的块会看到后文对角色的描述，
     造成"未来信息泄漏" — 比如角色尚未暴露的身份、尚未发生的关系变化。

     所以快照必须使用顺序前缀累积：合并到第 N 个块之前，拍一张快照。
     这个操作是纯内存操作（O(n)），不涉及 LLM，不是性能瓶颈。
     """
     relationship_map = {}
     entity_registry = {}
     open_thread_map = {}
     block_summaries = []
     alias_map = {}
     snapshots = []

     for packet in ordered_packets:
         # 先拍快照（只包含此块之前的信息）
         snapshots.append(
             self._snapshot(
                 packet["block_id"], block_summaries,
                 entity_registry, relationship_map,
                 open_thread_map, alias_map,
             )
         )
         # 再合并当前块
         self._merge_packet(
             packet, entity_registry, relationship_map,
             open_thread_map, block_summaries, [], alias_map, [],
         )

     return snapshots

 为什么同时需要树状合并和顺序快照

 │     组件     │     方法     │             用途             │       为什么这么做       │
 ├──────────────┼──────────────┼──────────────────────────────┼──────────────────────────┤
 │ 全局故事记忆 │ 树状并行合并 │ 最终聚合、种子分析、本体生成 │ 合并顺序不影响最终实体表 │
 ├──────────────┼──────────────┼──────────────────────────────┼──────────────────────────┤
 │ 块前快照     │ 顺序前缀累积 │ 上下文剧情分析的 LLM 输入    │ 必须保证只看到过去       │
 └──────────────┴──────────────┴──────────────────────────────┴──────────────────────────┘

 树状合并加速的是全局记忆的构建（用于 seed_analysis 和 ontology），不是快照生成。快照生成本身是纯内存操作（合并 dict/list），100 个块只需几十毫秒，不是管线瓶颈。

 _merge_two_segments 实现细节

 def _merge_two_segments(self, left: Dict, right: Dict) -> Dict:
     """合并两个相邻的记忆段。保持时间顺序（left 在 right 之前）。

     ★ 不使用 deepcopy — 直接构建新字典，避免大对象拷贝开销。
     """
     merged_entities = dict(left["entity_registry"])
     for name, entity in right["entity_registry"].items():
         if name in merged_entities:
             existing = merged_entities[name]
             # 合并 mention_blocks（去重）
             seen = set(existing["mention_blocks"])
             for b in entity["mention_blocks"]:
                 if b not in seen:
                     existing["mention_blocks"].append(b)
                     seen.add(b)
             # evidence 追加但限制总数
             for e in entity.get("evidence", []):
                 if len(existing["evidence"]) < 6 and e not in existing["evidence"]:
                     existing["evidence"].append(e)
             # summary：right 覆盖 left（后文更准确）
             if entity.get("summary"):
                 existing["summary"] = entity["summary"]
             # aliases 合并
             alias_set = set(existing.get("aliases", []))
             for alias in entity.get("aliases", []):
                 if alias not in alias_set:
                     existing["aliases"].append(alias)
                     alias_set.add(alias)
         else:
             merged_entities[name] = entity

     # 关系：按 (source, target) 合并 changes 列表
     merged_rels = dict(left.get("relationship_map", {}))
     for key, rel in right.get("relationship_map", {}).items():
         if key in merged_rels:
             merged_rels[key]["changes"].extend(rel["changes"])
         else:
             merged_rels[key] = rel

     # block_summaries：拼接（left 在前，right 在后）
     merged_summaries = list(left.get("block_summaries", [])) + list(right.get("block_summaries", []))

     # event_timeline：拼接并按 chapter_id 排序
     merged_events = list(left.get("event_timeline", [])) + list(right.get("event_timeline", []))
     merged_events.sort(key=lambda e: e.get("chapter_id", ""))

     # open_threads：合并，closed 的移除
     merged_threads = dict(left.get("open_thread_map", {}))
     for key, thread in right.get("open_thread_map", {}).items():
         if thread.get("status") == "closed":
             merged_threads.pop(key, None)
         else:
             merged_threads[key] = thread

     # alias_map：合并
     merged_aliases = dict(left.get("alias_map", {}))
     merged_aliases.update(right.get("alias_map", {}))

     # world_rules：去重合并
     seen_rules = set(left.get("world_rules", []))
     merged_rules = list(left.get("world_rules", []))
     for rule in right.get("world_rules", []):
         if rule not in seen_rules:
             merged_rules.append(rule)
             seen_rules.add(rule)

     return {
         "entity_registry": merged_entities,
         "relationship_map": merged_rels,
         "block_summaries": merged_summaries,
         "event_timeline": merged_events,
         "open_thread_map": merged_threads,
         "alias_map": merged_aliases,
         "world_rules": merged_rules,
         "block_count": left.get("block_count", 0) + right.get("block_count", 0),
     }

 合并正确性保证

 实体/关系合并是可交换的（commutative）— 合并顺序不影响最终实体注册表。时间顺序通过以下机制保证：
 - block_summaries 列表保持按 block_id 排序
 - event_timeline 按 chapter_id 排序
 - relationship.changes 按 block_id 排序
 - _merge_two_segments 始终保证 left 在 right 之前

 性能影响

 - 100 个块：7 轮合并（log₂100 ≈ 7），每轮最多 50 个并行合并操作
 - 树状合并加速的是全局记忆构建，不是快照生成
 - 快照仍然顺序生成（O(n)），但这是纯内存 dict/list 合并操作，100 个块耗时 < 100ms，不是管线瓶颈
 - 真正的时间瓶颈在 LLM 调用（分钟级），树状合并在此场景下收益有限但实现简单
 - 避免了 _merge_two_segments 中的 deepcopy（改为直接构建新 dict），减少内存压力

 兼容性

 - build_tree() 替代原有 build() 成为主方法
 - 原有 build() 保留但标记为 @deprecated，仅供测试对比用
 - 输出格式与 build() 完全一致：{"story_memory": {...}, "snapshots": [...]}
 - SeedExtractRunner 中直接调用 build_tree()

 Prompt Token 预算管理

 问题： 快照扩容到 8000 字 + 60 实体 + 锚点 + 指纹后，直接塞入 prompt 可能超出 LLM 上下文窗口或导致质量下降。

 解决方案： 新增 PromptBudgetManager，在注入 prompt 前按优先级裁剪。

 # 新建 backend/app/services/prompt_budget_manager.py

 MAX_PROMPT_INPUT_CHARS = 24000   # 约 8000 token（中文 ~3 字/token）

 # 各段优先级（数字越小越重要，超预算时从最后开始砍）
 SECTION_PRIORITY = {
     "主块正文":          1,    # 不可裁剪
     "骨架角色列表":      2,    # 裁减到 top 20
     "锚点世界状态":      3,    # 裁减到核心字段
     "上下文章节":        4,    # 可砍掉或截断
     "章节指纹":          5,    # 可砍掉
 }

 # 各段硬上限
 SECTION_CHAR_LIMITS = {
     "主块正文":          12000,  # 10 章 × 平均 1200 字
     "骨架角色列表":      1500,
     "锚点世界状态":      3000,
     "上下文章节":        4000,
     "章节指纹":          1500,
 }

 class PromptBudgetManager:
     """按优先级裁剪 prompt 输入，保证不超出 token 预算。

     ★ 线程安全：所有操作使用局部副本，不修改模块级常量。
     """

     def build_prompt(self, sections: Dict[str, str]) -> str:
         """输入各段文本，输出裁剪后的完整 prompt。"""
         # ★ 使用局部副本，避免修改全局 SECTION_PRIORITY
         local_sections = dict(sections)
         local_priority = dict(SECTION_PRIORITY)

         total = sum(len(v) for v in local_sections.values())
         if total <= MAX_PROMPT_INPUT_CHARS:
             return self._assemble(local_sections)

         # 超预算：按优先级从低到高裁剪各段到硬上限
         for section_name in sorted(local_priority, key=local_priority.get, reverse=True):
             if section_name not in local_sections:
                 continue
             limit = SECTION_CHAR_LIMITS.get(section_name, 2000)
             current = len(local_sections[section_name])
             if current > limit:
                 local_sections[section_name] = local_sections[section_name][:limit] + "\n[已截断]"
             total = sum(len(v) for v in local_sections.values())
             if total <= MAX_PROMPT_INPUT_CHARS:
                 break

         # 仍然超预算：删除最低优先级的整段（操作局部副本）
         while total > MAX_PROMPT_INPUT_CHARS and local_priority:
             lowest_key = max(local_priority, key=local_priority.get)
             local_sections.pop(lowest_key, None)
             del local_priority[lowest_key]
             total = sum(len(v) for v in local_sections.values())

         return self._assemble(local_sections)

 集成点： LocalBlockFactExtractor._extract_with_llm() 和 ContextualBlockAnalyzer._analyze_with_llm() 在构建 user_message 时，通过 PromptBudgetManager.build_prompt() 裁剪。

 class EntityResolutionService:
     """并发提取后的全局实体消歧。仅执行高置信度合并。"""

     MODULE_KEY = "entity_resolution"

     def __init__(self, llm_router: Optional[LlmRouter] = None):
         self.llm_router = llm_router or LlmRouter()

     def resolve(self, story_memory: Dict) -> Dict:
         """两步消歧流程。保守策略：宁可漏合并，不可误合并。"""
         entity_registry = story_memory["entity_registry"]
         alias_map = story_memory["alias_map"]

         # Step 1: 别名合并 — 如果 A 是 B 的已知别名（来自文本中明确的 "X又叫Y"），合并到 B
         entity_registry, alias_map = self._merge_known_aliases(entity_registry, alias_map)

         # Step 2: LLM 辅助消歧 — 将所有疑似重复的实体对交给 LLM 判断
         candidates = self._find_merge_candidates(entity_registry)
         if candidates:
             entity_registry, alias_map = self._llm_resolve_candidates(
                 entity_registry, alias_map, candidates
             )

         story_memory["entity_registry"] = entity_registry
         story_memory["alias_map"] = alias_map
         return story_memory

     def _find_merge_candidates(self, registry: Dict) -> List[Tuple]:
         """找出疑似重复的实体对。仅收集候选，不自动合并。"""
         names = list(registry.keys())
         candidates = []
         for i, a in enumerate(names):
             for b in names[i+1:]:
                 reason = None
                 # 子串关系且短名是长名的前缀/后缀："沈夜" vs "沈夜澜"
                 if len(a) >= 2 and len(b) >= 2:
                     if a in b or b in a:
                         reason = "substring"
                     # 编辑距离 1 且长度 >= 2："秦昭" vs "秦照"
                     elif self._edit_distance(a, b) <= 1:
                         reason = "typo"
                 if reason:
                     candidates.append((a, b, reason))
         return candidates

     def _llm_resolve_candidates(self, registry, alias_map, candidates):
         """调用 LLM 判断每组候选是否是同一实体。

         LLM 输入：两个实体的名字 + 各自的 summary + evidence + 出现章节
         LLM 输出：{merge: true/false, reason: "..."}

         ★ 为什么不用"共现检验"替代 LLM：
         "从未共现 → 同一人"规则误合并率太高。长篇小说中：
         - 两条支线的角色可能全书不共场但确实是不同人
         - 同门不同场景的师兄弟可能名字相似但不共场
         - 前期和后期不同阶段的角色可能不在同一块中出现
         只有 LLM 能理解 evidence 中的语义差异来做可靠判断。
         """
         client = self.llm_router.build_client(self.MODULE_KEY)
         for a, b, match_type in candidates:
             if a not in registry or b not in registry:
                 continue
             entity_a = registry[a]
             entity_b = registry[b]
             prompt = self._build_resolution_prompt(a, entity_a, b, entity_b, match_type)
             result = client.chat_json_value(
                 messages=[
                     {"role": "system", "content": ENTITY_RESOLUTION_SYSTEM_PROMPT},
                     {"role": "user", "content": prompt},
                 ],
                 temperature=0.1,
                 max_tokens=256,
             )
             if result.get("merge") is True:
                 self._merge_entities(registry, alias_map, a, b)
         return registry, alias_map

     def _build_resolution_prompt(self, name_a, entity_a, name_b, entity_b, match_type):
         return (
             f"候选匹配类型：{match_type}\n\n"
             f"实体A：{name_a}\n"
             f"  类型：{entity_a.get('entity_type', '未知')}\n"
             f"  摘要：{entity_a.get('summary', '无')}\n"
             f"  证据：{entity_a.get('evidence', [])[:3]}\n"
             f"  出现块：{entity_a.get('mention_blocks', [])}\n\n"
             f"实体B：{name_b}\n"
             f"  类型：{entity_b.get('entity_type', '未知')}\n"
             f"  摘要：{entity_b.get('summary', '无')}\n"
             f"  证据：{entity_b.get('evidence', [])[:3]}\n"
             f"  出现块：{entity_b.get('mention_blocks', [])}\n\n"
             f"这两个实体是否是同一个角色/组织？"
         )

 def build_anchor_context(block: Dict, anchors: Optional[Dict]) -> str:
     """为给定块构建最近锚点的上下文文本。"""
     if not anchors:
         return "未提供前情锚点。"
     # 找到 block_id 之前的最近锚点
     nearest = None
     for anchor in anchors.get("anchors", []):
         if anchor["block_range"][-1] < block["block_id"]:
             nearest = anchor
     if not nearest:
         return "当前块位于小说开头，无前情锚点。"
     ws = nearest["world_state"]
     lines = []
     if ws.get("active_characters"):
         chars = ", ".join(f"{c['name']}({c.get('status','active')},{c.get('last_action','')})"
                          for c in ws["active_characters"][:15])
         lines.append(f"当前活跃角色：{chars}")
     if ws.get("active_organizations"):
         orgs = ", ".join(f"{o['name']}({o.get('status','')})"
                         for o in ws["active_organizations"][:8])
         lines.append(f"当前活跃组织：{orgs}")
     if ws.get("key_relationships"):
         rels = ", ".join(f"{r['source']}↔{r['target']}({r['state']})"
                         for r in ws["key_relationships"][:10])
         lines.append(f"关键关系：{rels}")
     if ws.get("open_plot_threads"):
         lines.append(f"开放线索：{'、'.join(ws['open_plot_threads'][:8])}")
     if ws.get("recent_events_summary"):
         lines.append(f"最近事件：{ws['recent_events_summary'][:300]}")
     return "\n".join(lines)

 def build_fingerprint_context(block: Dict, skeleton: Optional[Dict], window: int = 2) -> str:
     """构建前 N 个块的章节指纹上下文。"""
     if not skeleton:
         return ""
     sketches = skeleton.get("chapter_sketches", [])
     # 找到当前块之前 window 个块的指纹
     block_order = int(block["block_id"].replace("block_", ""))
     prev_sketches = [s for s in sketches
                      if s.get("order", 0) < block.get("owned_chapter_range", {}).get("start_order", 0)]
     recent = prev_sketches[-window * 10:]  # 前 2 个块的章节
     if not recent:
         return ""
     lines = []
     for s in recent:
         fp = s.get("fingerprint", "")
         if fp:
             lines.append(f"第{s['order']}章({s.get('title', '')}): {fp}")
     return "\n".join(lines[-6:])  # 最多展示最近 6 章指纹

 LLM 模块校验

 管线启动前，SeedExtractRunner 新增 _validate_llm_modules() 方法：

 REQUIRED_LLM_MODULES = [
     "local_block_facts",             # 块内事实提取
     "contextual_block_analysis",     # 前情快照剧情分析
     "anchor_point_summary",          # 锚点摘要生成（新增）
     "entity_resolution",             # 实体消歧（新增）
     "story_ontology",                # 本体生成（现有，原名 story_ontology）
 ]

 def _validate_llm_modules(self):
     """启动前校验所有必需 LLM 模块已绑定模型。未绑定直接报错。

     ★ 注意：当前 SeedExtractTaskService 没有 llm_router 属性。
     LlmRouter 需要通过 LlmSettingsService 构建。校验方式：
     对每个 module_key 调用 llm_router.build_client()，
     如果底层 LlmSettingsService 找不到绑定，会抛出 ValueError。
     """
     from .llm_router import LlmRouter
     router = LlmRouter()  # 使用默认 settings_service
     missing = []
     for module_key in REQUIRED_LLM_MODULES:
         try:
             router.build_client(module_key)
         except (ValueError, Exception):
             missing.append(module_key)
     if missing:
         raise ValueError(
             f"以下 LLM 模块未在全局设施面板中绑定模型，无法启动分析：{', '.join(missing)}。"
             f"请在 LLM 设施面板中为这些模块配置渠道和模型。"
         )
