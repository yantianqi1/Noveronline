# 数据库真相源矩阵

更新时间：2026-06-08（seed / graph / worldline DB-first 增量）

## 目的

这份矩阵基于当前代码库实际读写路径，盘点每个业务域/业务对象的：

- 当前来源
- 目标统一表
- 当前真相源状态
- 迁移优先级
- 切换完成判定条件
- 已知 legacy 读取点

> 说明：这里的“当前来源”以代码现状为准，不以迁移计划目标为准。

## 状态图例

- **已统一**：主库已经是运行时主读写源。
- **DB 镜像 + legacy 真相**：主库有表，但运行时仍会从 JSON / 旧 SQLite / 文件系统回填或同步。
- **混合**：运行时同时依赖主库与 legacy 存储。
- **仅 legacy / 目标未落表**：当前仍直接依赖 legacy 文件，或现有 schema 尚无明确承载表。

## 关键结论

### 1. 已经比较接近统一的域

- **LLM 设施**：运行时基本已经完全主库化。
- **任务运行时**：已经由 `task_runs` 承载。
- **资产库 / 手稿块**：主写路径已经在统一库。
- **图谱快照输出**：对外读取已转向 `graph_*` 表。

### 2. 仍然阻塞“单一真相源”目标的核心域

- **章节上下文 / writer canon 数据**：`ChapterMetaService` 的世界规则和上一章结尾已完全切到结构化主库；`ChapterContextPackBuilder.build_options()` / `build()` 已不再读取 `chapter_segments` / `chapter_continuity` / `story_memory` / `consistency_report` artifact，旧 continuity 由迁移器导入章节表和项目设置。下一步重点是减少 seed 输出链、graph 输入和部分 API 对 artifact payload 形状的正式依赖。
- **worldline container_dir 兼容路径**：session/runtime 数据已 DB-backed，`resolve_container()` 仍保留路径字符串兼容，但不创建空目录；候选列表只枚举已存在目录，后续可继续瘦身 API/服务签名。
- **seed / chapter / graph artifact payload**：chapter-context、graph build、worldline source、unified seed assets、novel seed/archive 读入口和 GlobalDataLinker 已具备结构化表 fallback，其中 graph build、worldline source 和 unified seed assets 已改为结构化输入优先；seed_analysis 的基础实体/关系、reading notes 的 runtime facts 与 agent_profiles 的基础角色档案字段已经开始直接写结构化表，并且统一资产 seed reader、档案生成入口和全局打通入口都能从 `entities.profile_json` 还原角色 Agent 档案。`ontology` 已可由 DB project meta fallback 提供基础 entity types；剩余要决定哪些 payload 继续拆到结构化表，哪些正式保留为 K-V payload。
