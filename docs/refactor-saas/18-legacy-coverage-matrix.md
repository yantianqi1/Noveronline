# 18. Legacy Coverage Matrix

更新时间：`2026-07-08`

## 目的

本矩阵用于证明 SaaS 重构不会漏掉旧功能。后续每个实现阶段都要更新本文件，把状态从 `planned`（必须带 owner/wave）推进到 `implemented`、`verified`。

状态：

- `planned`：文档已有目标设计，且必须在同一状态单元写明 owner/wave。
- `implemented`：代码已实现。
- `verified`：测试或手工验收通过。

当前仍保留的 `planned` 项必须显式标注 owner/wave；未标注 owner/wave 的裸状态视为 Wave 0 治理不通过。

## Wave 0 治理状态规则

更新时间：`2026-07-07`

- Wave 0 只校准文档和验收矩阵，不声明任何产品代码实现完成。
- 剩余 `planned` 行允许存在，但必须写成 `planned (owner: Wave X - name)` 或在同一状态文本中明确后续 wave/owner。
- candidate -> canon、draft -> manuscript 仍只能通过显式用户动作；公共 API/UI/events/logs/trace 不得暴露 prompt、provider response、raw body/content、API key、encrypted credential、`credential_ref`、object key、draft 或 manuscript 正文。
- Worldline 仍是单世界 `current_world`；旧 branches/comparison 只允许作为 Gone/deprecated compatibility，不恢复为主模型。

## 覆盖验收规则

一个旧功能只有满足以下条件才可从 `planned`（含 owner/wave）升级为 `verified`：

1. 有新 API 或明确不需要 API 的 UI/worker 实现。
2. 有数据模型承载。
3. 有权限和 tenant 隔离。
4. 有错误状态，不使用假成功。
5. 有测试或手工验收记录。
6. 文档更新到对应模块。
