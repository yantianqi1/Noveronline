# 写作台「对话优先」界面重构方案

更新时间：`2026-07-14`

## 文档职责

本文是写作台（Writer）界面信息架构的重构设计方案，回答「如何把当前三栏工作台简化为：对话是唯一入口、产物是唯一主角、过程默认折叠」。

- 本文只定义目标体验、信息架构与展示规则，不是当前进度真相源。
- 实施前仍按 `DEVELOPMENT_PLAN.md` → `24-current-development-progress.md` → 活动任务板 → 当前 worktree 顺序核对事实。
- 本文与 `34-author-friendly-experience-plan.md`（作者语言、安全边界）和 `35-author-friendly-implementation-plan.md`（AF 任务）互补：34/35 解决「说什么话、守什么底线」，本文解决「页面长什么样、信息怎么分层」。
- 后端契约（`startWriterRun`、writer 公开事件、draft adoption、Facility module binding）保持不变；这是一次展示层与信息架构重构，不是运行时重写。

## 与 manuscript-primary 约束的关系

仓库硬约束要求 Writer 保持 manuscript-primary（产物主导、Agent 不占半屏）。本方案不违反它，而是把它推进一步：

- **产物画布仍然是最大、最主导的区域**——这一点不变。
- 变化在于：Agent 侧从「dock 里的一堆面板」收敛为「一条对话流 + 一个 composer」，结构轨、四 tab、上下文勾选、技术面板全部退出常驻布局。
- 一句话概括新形态：**对话是唯一入口，画布是唯一舞台，过程是一行可展开的状态。**

## 一、当前界面的主要问题

基于当前 worktree 的实际代码（`writer-workbench-shell.tsx`、`writer-product-workspace.tsx`、`project-nav.tsx`、`workbench-polish.css` 等）：

1. **面板概念过多。** 桌面端同时存在 7 个并列概念：结构轨、manuscript/structure/review/studio 四个 tab、Agent thread、composer，再叠加外层项目侧栏与顶部工具条。用户第一眼无法回答「我该在哪里开始」。
2. **双结构导航职责分裂。** 左侧 `writer-structure-rail` 只读导航，章节 CRUD 却在中间 structure tab；用户必须先理解「点左边选、去中间改」这条隐藏规则。
3. **候选稿与正式手稿双轨模型靠文案硬撑。** Agent 输出在右侧 dock，采用后才进中间画布。这个模型本身合理（作者正文安全），但目前靠 4 处空态文案反复解释，说明布局没有表达出这层关系。
4. **执行过程半暴露。** 活动时间线、连接状态 banner、run 状态 chip、阶段小字、审批卡、候选稿操作全部常驻 dock；工具结果卡、原始事件、trace 又藏在「技术详情」modal。主 IA 与调试 IA 边界模糊，普通作者看到大量与写作无关的机器信息。
5. **Studio tab 过载。** 大纲、书籍计划、预设、词库、一键命令、去重、导出全部堆在一个 tab，与 review/manuscript 的边界不清。
6. **首页（overview 与写作台空态）承担了教程职责。** 双入口卡、readiness 门控、三步引导、多段「候选稿 vs 手稿」解释同时出现，认知负担来自「先学会系统再开始写」。
7. **URL 状态爆炸。** `runId/traceId/draftId/chapterId/sceneId/blockId/commandId/planningRunId/after_event_id/...` 组合驱动页面，恢复/回放表单遍布主界面。
8. **移动端两层 tab 切换。** 项目底栏四切 + Writer 内三切（结构/手稿/Agent），且移动默认 Agent、桌面默认手稿，心智模型不一致。
9. **上下文选择前置暴露。** composer 下方常驻「添加创作上下文」的资产/图谱/世界线三列勾选，把「Agent 应该自己检索」的工作提前压给了用户。
10. **缺少统一产物中心。** 候选稿、正文块、审校结果、导出文件分散在 dock、三个 tab 和折叠 meta 里，没有「我这次任务得到了什么」的单一答案。

## 二、新的信息架构

### 2.1 三层心智模型

整个写作台只保留三层，任何 UI 元素必须能归入其中一层：

| 层 | 内容 | 可见性 |
|---|---|---|
| **对话层（入口）** | composer、对话消息、示例任务、任务状态行 | 常驻，但视觉次于产物 |
| **产物层（主角）** | 手稿画布、候选稿预览、审校报告、大纲/计划文档、导出文件 | 主区域最大化展示 |
| **过程层（按需）** | 活动明细、工具调用参数、原始事件、trace、回放游标 | 默认折叠为一行状态；逐级展开 |

### 2.2 页面形态：一个页面，两种状态

不再用「布局」区分功能，而用「状态」区分页面形态：

- **起点态（Home state）**：项目没有进行中的任务、或用户点「新任务」时。整页只有：一句价值说明、居中大 composer、3–4 个示例任务、最近产物/最近章节入口。没有任何栏。
- **任务态（Task state）**：发出指令或打开既有章节后。两区布局：左侧**对话流**（窄，约 0.8fr / 380px），右侧**产物画布**（宽，约 1.6fr）。对话流承载任务叙事，画布承载产物。

从起点态到任务态是同一路由内的状态迁移（composer 从页面中央「落位」到左栏底部），给用户「我说的话变成了正在推进的任务」的连续感。

### 2.3 导航收敛

- 项目侧栏（`project-nav.tsx`）保持项目级导航职责，不进入写作台内部结构。
- 写作台内部删除结构轨与四 tab 常驻导航，替换为两个按需入口：
  - **章节切换器**：画布标题栏上的下拉（书名 › 第 N 章），点开是章节/场景树，含新建章节。取代 `writer-structure-rail` + structure tab 的导航部分。
  - **命令面板 ⌘K**（已有 `WriterCommandPalette`）：跳章节、开审校、导出、打开大纲等低频动作的统一入口。
- review / studio 的能力不消失，改为**由对话触发、在画布展示**（见第五节展示规则）。

### 2.4 对话即任务历史

- 以持久 thread（已有 `listWriterThreads` 后端能力）为唯一叙事主轴，弃用「单次 run 为中心」的 UI 拼装。
- 每次 run 在对话流中表现为：用户消息 → 任务状态行（可展开）→ 产物卡片。
- URL 只保留 `chapterId` 与 `taskId`（= runId 的作者化命名）两个作者可见参数；`traceId/after_event_id/draftId` 等恢复参数全部移入技术详情抽屉内部的表单，不再驱动主界面。

## 三、核心用户流程

### 流程 A：新用户第一次写作（零教程）

```text
进入写作台（起点态）
  -> 看到一句话说明 + 大输入框 + 示例任务
  -> 点示例「帮我写一个玄幻故事的开场」或直接输入
  -> （未连接 AI 服务时：此刻才弹出 34 号方案的三步连接向导，完成后自动继续）
  -> 页面迁移到任务态：左侧出现对话，状态行「正在分析需求…」
  -> 状态行依次变为「正在查看本书设定」「正在起草正文」（作者语言，34/35 词典）
  -> 候选稿在画布流式出现（打字机效果，来自 writer.token）
  -> 完成后画布顶部出现操作条：[采用为手稿] [继续修改] [复制] [导出]
  -> 点「采用为手稿」，画布无缝切换为正式手稿编辑态（TipTap）
```

关键点：连接 AI 服务的门控**后置到第一次真正需要时**，而不是首页常驻 readiness 面板。

### 流程 B：老用户回来继续写

```text
进入写作台
  -> 直接恢复上次章节的画布（localStorage + chapterId）+ 该章节的对话流
  -> 在画布里手写，或选中一段文字
  -> 选区浮条出现 [请 Agent 修改]，点击后浮条变 mini composer
  -> 输入「改得更紧张一些」发送
  -> 对话流新增一条任务，状态行推进，diff 结果在画布内联展示
  -> 接受/保留（走 AF-01 的冲突安全契约）
```

### 流程 C：非正文任务（大纲、审校、导出）

```text
在 composer 输入「帮我审一遍第三章」/「给这本书列一个 20 章的大纲」/「导出全书正文」
  -> Agent 识别意图（或用户点 composer 上方的意图 chip）
  -> 状态行推进
  -> 产物以对应形态出现在画布：审校报告卡片列表 / 大纲文档 / 导出文件下载卡
```

这条流程是「弱化 studio/review tab」的替代品：能力入口从 tab 迁移到对话。

### 流程 D：出错与恢复

```text
任务失败
  -> 对话流中该任务的状态行变为「未完成」+ 一句作者能懂的原因（34 号方案错误词典）
  -> 提供 [重试] [修改要求后重试]
  -> 断线时状态行显示「连接中断，正在重连…」，重连逻辑沿用现有 SSE fallback
  -> 事件游标、trace 导出等排查动作只存在于技术详情抽屉
```

## 四、页面布局与关键组件

### 4.1 任务态布局

```text
.writer-agent-layout[data-layout="conversation-first"]
├── 左区 .writer-conversation-rail（~380px，flex column）
│   ├── 对话滚动区（thread 消息 + 任务状态行 + 产物摘要卡）
│   └── composer 常驻底部（自动增高 textarea + 发送 + @引用 + 意图 chip）
└── 主区 .writer-artifact-canvas（主导）
    ├── 画布标题栏：章节切换器 ▾ ｜ 字数 ｜ 保存状态 ｜ [⌘K] [⋯]
    ├── 画布主体（按产物类型切换渲染器）
    └── 画布操作条（产物完成时出现：采用/继续修改/复制/导出）
```

### 4.2 组件映射（复用为主）

| 新概念 | 处置 | 现有组件 |
|---|---|---|
| 起点态首屏 | 新增 | 新 `writer-home-state`（复用 composer 组件居中渲染） |
| 对话流 | 改造 | `WriterAgentThread`（thread-first，run 卡片化） |
| 任务状态行 | 新增 | 新 `WriterTaskStatusLine`，数据源复用 `writer-event-store` 聚合 |
| 活动明细（展开层） | 复用 | `WriterActivityTimeline`（移入状态行展开区，接 author-copy 词典） |
| composer | 改造 | `WriterAgentComposer` + `WriterComposerInput`（模式 chip 改意图 chip，可不选） |
| 上下文引用 | 改造 | `ContextPickers` 三列勾选 → composer 内 `@` / 回形针弹出搜索选择器 |
| 产物画布 | 改造 | `WriterProductWorkspace` 拆解：manuscript 编辑器升为画布默认体；review/studio 面板改为按需渲染器 |
| 章节切换器 | 合并 | `WriterStructureNav` + structure tab 导航 → 画布标题栏下拉树 |
| 流式候选稿 | 迁移 | `WriterLiveDraft` 的正文拼接从 dock 迁到画布；活动时间线留在状态行 |
| 审批卡 | 保留 | `WriterApprovalCard` 内嵌对话流，视觉升级为醒目卡片 |
| 技术详情 | 保留 | `TechnicalDetailsDrawer` 原样保留（含事件回放、trace 导出、工具结果卡），入口移至 [⋯] 菜单 |
| 移动切换 | 简化 | `WriterMobileSwitch` 三切 → 双面板手势/按钮切换（见第八节） |

### 4.3 任务状态行（核心新组件）

对话流中每个任务显示为一行可展开的状态，聚合规则：

```text
折叠态（默认，单行）：
  ⏳ 正在分析需求               （run started，无工具事件）
  🔍 正在查阅资料 · 已完成 3 项   （tool started/completed 聚合计数）
  ✍️ 正在起草正文 · 812 字       （writer.token 累计字数，不显示 token 本身）
  ✅ 已完成 · 生成候选稿 1,204 字  （run completed）
  ⚠️ 未完成 · 模型服务无法访问     （run failed + 作者化原因）

展开态（点击展开）：
  ├ 查看本书设定        已完成
  ├ 核对人物关系        已完成
  ├ 查看前文           已完成
  ├ 起草正文           进行中
  └ [查看技术详情]      （权限内可见，打开抽屉）
```

- 折叠态永不显示：工具名、参数、事件 ID、字节数、英文枚举。
- 展开态第一层显示作者化步骤名 + 状态（即现 `WriterActivityTimeline` 接 35 号词典后的形态）。
- 工具参数、调用日志、原始 payload 只在技术详情抽屉（第二层展开）出现。

## 五、对话、执行状态、工具调用与最终产物的展示规则

### 5.1 对话消息

| 类型 | 规则 |
|---|---|
| 用户消息 | 右对齐气泡；附带的 @引用显示为小 chip |
| Agent 回复 | 不重复贴产物全文；只给一句结果摘要 + 产物卡片（「我写好了一段 1,204 字的开场，已放在右侧」） |
| 任务状态行 | 见 4.3；每个任务恰好一条，原地更新，不刷屏 |
| 审批请求 | 醒目卡片 + [同意]/[拒绝]，阻塞期间状态行显示「等待你的确认」 |

### 5.2 执行状态映射（事件 → 状态行）

| 公开事件 | 折叠态文案 | 展开态 |
|---|---|---|
| `writer.run.started` | 正在分析需求 | 任务开始时间 |
| `writer.tool.started/completed` | 正在查阅资料 · 已完成 N 项 | 每个工具一行作者化名称（35 号词典） |
| `writer.token` | 正在起草正文 · N 字 | 不进时间线（沿用现有跳过逻辑） |
| `writer.draft.saved` | 已保存候选稿 | 候选稿卡片出现在对话流 + 画布 |
| `writer.approval.required/resolved` | 等待你的确认 / 已确认 | 审批卡 |
| `writer.revision.proposed` | 修改建议已准备好 | 画布内联 diff |
| `writer.run.completed/failed/cancelled` | 已完成 / 未完成 / 已取消 | 失败原因（作者化）+ 重试 |

### 5.3 工具调用

- 默认只贡献「已完成 N 项」计数。
- 展开层显示作者化步骤名，不显示参数与结果。
- 结构化工具结果卡（`ToolResultCards`）保留在技术详情抽屉，服务排查而非日常写作。
- 失败的工具在展开层保留醒目标记（沿用现有「run 结束后隐藏成功噪音、保留 failed」的聚合逻辑）。

### 5.4 最终产物（画布渲染器）

| 产物类型 | 画布形态 | 操作条 |
|---|---|---|
| 候选稿 | 流式正文，完成后加「候选稿」水印边框 | 采用为手稿 · 继续修改 · 复制 · 丢弃 |
| 正式手稿 | TipTap 编辑器（现有），选区浮条触发修订 | 保存状态 · 版本 · 导出 |
| 修订建议 | 手稿内联 diff（现有 `writer-revision-diff`） | 接受 · 保留原文 · 比较两版（AF-01 契约） |
| 审校报告 | issue 卡片列表，逐条定位到正文 | 接受 · 忽略 · 全部处理 |
| 大纲/书籍计划 | 结构化文档卡 | 编辑 · 应用为章节结构 |
| 导出文件 | 下载卡（文件名/大小/格式） | 下载 · 重新生成 |

规则：**产物永远出现在画布，对话流只放摘要卡**；点摘要卡即把画布切到该产物。产物视觉优先级 > 对话 > 状态行 > 技术细节。

### 5.5 候选稿双轨模型的视觉表达

用画布状态表达而非文案解释：候选稿带虚线边框 + 「候选稿」角标，采用后动画过渡为无边框正式手稿。空态解释文案从 4 处缩减为候选稿卡片上的一句：「这是候选稿，采用后才会进入你的正式手稿。」

## 八、桌面端与移动端响应式策略

| 断点 | 布局 |
|---|---|
| ≥1180px | 对话 rail（380px）+ 产物画布；起点态整页居中 |
| 960–1180px | 对话 rail 收窄至 320px；画布优先保宽 |
| <960px（移动） | 单面板：对话 ⇄ 产物二态切换，顶部分段控件 + 左右滑动手势 |

移动端细则：

1. **默认进入对话面板**（移动场景「说需求」优先），但产物生成完成时自动提示并一键切到产物面板；上次编辑的章节从产物面板恢复。
2. 产物面板 = 全屏画布，操作条吸底；采用/接受等主操作按钮 ≥44×44px，正文 ≥16px（35 号方案无障碍约束）。
3. composer 沿用现有键盘 inset（`--writer-keyboard-inset`）与 immersive 模式（隐藏 header，sticky 切换条）。
4. 项目级 `MobileTabBar` 不变；Writer 内部从三切降为二切后，两层导航的组合复杂度显著下降。
5. 状态行在移动端同样是唯一过程展示；展开层为底部抽屉（bottom sheet），技术详情在移动端仅入口保留于 [⋯]。
