# 37. 前端模块清单（Agent 开发指引）

更新时间：`2026-07-22`

## 文档职责

本文只回答一件事：**`apps/web` 需要具备哪些前端模块与产品面。**

- 给后续 AI coding agent 当模块范围真相源：缺什么、有什么、什么不该做。
- 不规定实现顺序、技术选型、组件拆分或编码步骤。
- 不替代领域设计细节；各模块的交互与契约仍以对应专题文档和当前 `apps/api` 为准。
- 进度与是否已落地以 `24-current-development-progress.md` 和当前 worktree 为准，不以本文推断完成度。

前端唯一代码与构建上下文：`apps/web`。不得重建根目录旧 `frontend/`。

---

## 产品壳（所有模块共用）

前端需要有统一的作者侧应用壳，而不是一组互不相关的页面：

| 需要有 | 说明 |
|---|---|
| 公开入口 / 落地 | 未登录可达的产品入口（可极简） |
| 认证后应用壳 | 登录后的统一导航、上下文与用户入口 |
| 工作区 / 项目切换 | 作者能看到自己的工作区与项目，并能进入某个项目 |
| 项目内一级导航 | 进入项目后固定出现下列工作台入口（见下节） |
| 用户菜单 | 账号信息、登出等基础操作 |
| 跨模块任务进度感知 | 长任务（Seed / Graph / Writer 等）有可恢复的进度与失败态展示入口，不假装成功 |
| 空状态与轻量说明 | 各模块内的引导与说明；不单独恢复旧 `/guide` 长页 |

项目内一级导航必须覆盖：

```text
总览（含导入与分析）
故事图谱
资产库
世界线
角色控制
写作台
设置
```

说明：旧文档曾把「总览」与「导入与分析」拆成两个一级入口；前端以**同一产品面**交付，不再单独占一级导航「导入与分析」。

## 账号与协作模块

| 模块 | 需要有的产品面 |
|---|---|
| 登录 | 邮箱密码登录；会话建立；失败与 CSRF/会话错误可见 |
| 注册 | 自助注册；创建个人工作区与首项目后进入产品 |
| 找回密码（Recovery） | 请求重置与凭 token 重置密码的完整页面流 |
| 会话管理 | 查看/撤销本账号会话（可放在设置或账号区） |
| 修改密码 | 已登录用户改密 |
| 邀请接受 | 凭邀请链接/token 加入工作区或项目的落地页 |
| 成员管理 | 工作区成员与项目成员的查看、角色变更、移除；含 last-owner 等保护提示 |
| 邀请发出 | 管理员可发出/重发/撤销邀请（可挂在设置或成员面板） |

## 工作区与项目模块

| 模块 | 需要有的产品面 |
|---|---|
| 书架 / 工作区首页 | 登录后的项目列表主面；按工作区组织项目 |
| 工作区切换 | 多工作区时可见切换；单工作区时可隐藏切换器 |
| 项目创建 | 在工作区内新建项目 |
| 项目基础管理 | 重命名等项目元数据维护（权限内） |
| 项目入口 | 从书架进入某个项目的工作台壳 |

## 项目工作台模块

以下每个模块都是**独立产品面**，后端已有对应能力；前端需要各自有可进入、可完成主任务的界面。

### 总览（含导入与分析）

作者进入项目后的第一屏，并把「上传 → Seed 分析」放在同一面完成，不拆成两个一级模块。

需要能回答：项目现在到哪一步、数据是否就绪、有哪些进行中/失败任务、下一步该做什么；同时能在本页完成原文导入与分析。

至少需要：

- 项目阶段 / 就绪度
- 最近任务与活动
- 空项目时的明确入口（例如从想法开写、上传已有文本）
- 原文上传（TXT / MD / PDF）
- 开始分析 / 重试 / 断点续传
- 实时或可恢复的 Seed 阶段进度
- 失败可见（阶段、摘要、可操作恢复），禁止伪装完成
- 源文件与分析运行历史的查看入口
- 未处理候选项 / 待办的汇总入口
- 跳转到其他工作台的清晰路径

领域细节可对照 `05-overview-dashboard.md` 与 `06-seed-pipeline.md`；前端仍按**一个总览面**实现。

### 故事图谱

故事世界地图：构建、浏览、筛选、选中、候选采用。

至少需要：

- 图谱构建 / 刷新入口
- 可读的图谱浏览画布（节点、边、布局、缩放平移等基础交互）
- 聚类 / 筛选 / 搜索
- 节点与边详情、证据入口
- 候选采用（显式确认，禁止静默自动采用）
- 羁绊等构图类生成入口（若产品仍提供）

### 资产库

小说系统内容的统一入口：角色、设定、关系、伏笔、规则、档案、手稿相关资产等。

至少需要：

- 资产列表与类型/来源/状态筛选
- 搜索
- 资产详情（内容、结构化字段、关联、版本）
- 候选 ↔ 正典的审阅与采用/拒绝
- 版本查看与恢复（catalog 能力）
- 集合 / 归档类组织入口（产品已提供的部分）

### 世界线

单世界剧情推演与实验（`current_world`）。

至少需要：

- 推演会话的创建与查看
- 目标启动 / 准备 / 步进或自动演化入口
- 变量注入
- 时间线与事件流
- 候选事件的采用 / 修改
- 保存路径与可引用结果

不需要：旧多分支对比、`/branches`、`/comparison` 类多世界分支产品面。

### 角色控制

作者以第一人称进入角色，在当前世界节点互动写作。

至少需要：

- 选择角色并开始互动
- 回合对话 / 事件流
- 提案查看与采用
- 将互动结果转写为章节草稿并衔写作台的路径
- 互动状态管理

### 写作台

主写作界面。产品形态约束：

- **稿件主导（manuscript-primary）**：主画布是连续稿件文档
- **conversation-first**：右侧常驻 Writer Agent dock（连续 thread + 常驻 composer）
- 画布视图：稿件 / 章节（结构） / 审校 / 工具

至少需要：

- 连续稿件阅读与就地编辑
- 章节 / 场景 / 片段结构管理
- Writer Agent 对话、流式活动、取消与失败恢复
- 候选稿显式采用（不得静默覆盖作者正文）
- 审校（Reviewer）结果与问题处理
- 书籍计划、大纲、预设、词库等写作辅助（可收在工具/结构视图）
- 去重约束相关入口
- 手稿导出
- 命令面板 / 快捷操作入口（产品已定义的部分）

写作台是主写作面；稿件工作区与导出可以嵌在写作台内，不必再占一级导航。

### 设置

项目与工作区级配置面。

至少需要：

- 项目设置入口
- LLM 模块绑定覆盖（项目级）
- 用量 / 配额相关只读或管理面（权限内）
- 成员与邀请（若未在独立成员页完成，则在此可达）
- 会话与安全相关入口的可达性

租户级 **LLM 设施**（渠道、模型目录、同步、provider health）需要有独立可管理界面，可挂在工作区/租户设置，而不是旧的孤立 `/llm-facility` 长页。

## 嵌在工作台内、不必单独占一级导航的能力

这些能力后端已有，前端需要有对应 UI，但通常挂在上述模块内部：

| 能力 | 通常挂载处 |
|---|---|
| 工作流 / SSE 进度与重连 | 总览（含 Seed）、各长任务模块 |
| 手稿块编辑、编译、导出下载 | 写作台 |
| Reviewer 审校跑批与 issue 处理 | 写作台 · 审校 |
| 书籍计划生成 / 大纲 | 写作台 · 工具或结构 |
| 资产蒸馏 / 提案轨（zero-start 相关） | 写作台与/或总览空项目路径 |
| Agent 活动与受限 trace 查看 | 各 Agent 模块的诊断/详情，不默认主 UI 堆砌原始事件 |
| 计费用量只读 | 设置 / LLM |

---

## 明确不需要的前端模块

下列内容**不要**作为前端模块恢复或新建：

- 根目录旧 `frontend/` 或任何 Vite 兼容壳
- 旧蓝色 Writer 长页、`writer-studio-grid`、折叠 composer、深色 `writer-agent-rail` 作为验收基线
- OAuth / MFA 等已退役认证面
- 多分支 worldline 对比与分支管理产品面
- Twitter / Reddit / 舆情分析等上游旧项目语义页面
- 用 stub / mock 假后端“跑通”的演示页或写死领域数据页
- 仅为调试存在、对作者无任务价值的控制台堆砌（技术详情可折叠，不得占主 IA）
