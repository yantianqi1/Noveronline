# 10-隐性语义与底层兼容矩阵

## 1. 目标

当前 `06` 和 `09` 已覆盖大部分显性功能，但仓库中还有大量“不是页面功能，却已经被测试固化”的底层行为语义。本文件用于把这些隐性语义显式纳入迁移范围，避免重构后主链能跑但行为细节漂移。

---

## 2. 覆盖原则

- 只要已有测试明确断言某种行为，该行为就属于本次重构必须承接的语义。
- 这些语义不能被笼统归入“实现细节”，必须在新系统中有明确归属：`contract / workflow / adapter / response policy / migration rule / test case`。
- 未出现在本矩阵中的底层测试语义，一律视为未完全迁移。

---

## 3. 必须承接的隐性语义

| 语义类别 | 现有事实来源 | 新系统承接要求 |
|---|---|---|

## 4. 落地位置

这些语义必须分别进入以下位置：

- `contracts`：响应头、错误码、SSE 事件形状、DTO 约束
- `workflow-platform`：operation 失败、恢复、终止语义
- `llm-facility`：并发、超时、模型绑定报错
- `writer`：candidate 隐藏、prompt budget、文本保真
- `project/seed-analysis`：文件解析、显式模式、payload 归一化
- `graph`：本地图构建、图快照读取、模板配置
- `migration`：archive memory、worldline event、chapter meta 历史链

---

## 5. 验收规则

只有同时满足以下条件，才算隐性语义完成：

1. 本文列出的每一类语义都有对应新测试。
2. 对应新测试已经进入 `unit / integration / workflow / contract / e2e` 的合适层级。
3. 迁移 rehearsal 中至少抽样验证以下 4 类：
   - orphan task / failed operation
   - archive memory timeline
   - graph query
   - writer candidate visibility
4. 不存在依赖“默认值成功”或“静默 fallback”的路径。
