# 00-重构总控与并行执行总览

## 1. 文档目标

本文件是本轮 `MiroFish-Novel` 重构的唯一总控入口，用来把 `01-14` 的专题文档收口成一套可执行、可并行、可验收、可回滚的完整方案。

本轮重构的固定边界：

- 只覆盖当前 `MiroFish-Novel` 仓库**已经存在**的功能、页面、接口、测试语义和数据语义。
- 不把老 `MiroFish` 中尚未进入本仓库的能力强行并入本次重构范围。
- 采用整体换新技术栈：`React + TypeScript + FastAPI + PostgreSQL + MinIO + Redis + Temporal`。
- 对外采用“一次切换”：最终交付为 `新前端 + 新 API + 新数据层 + 新工作流`，不保留长期新旧双跑。
- 对内采用“阶段化重建”：先冻结 contracts 和迁移基线，再按模块并行建设，最后只在所有闸门通过后正式切换。

## 4. 执行原则

### 4.1 对外一次切换，对内阶段推进

- 重构期间可以做迁移 rehearsal、影子对账、只读比对。
- 不允许把“暂时兼容”当成最终交付架构。
- 切换日之前，旧系统只作为只读事实源和迁移输入。
- 切换日之后，所有正式流量进入新系统。

### 4.2 先 contracts，后并行模块

所有并行开发都以以下基线为前置：

- 功能覆盖矩阵冻结
- 接口覆盖清单冻结
- 测试语义矩阵冻结
- 数据字段映射冻结
- OpenAPI / DTO / error code / SSE event schema 冻结

没有完成以上冻结，不允许 subagent 自由并行写业务实现。

### 4.3 前后端必须同时完整

本轮不接受以下伪完成状态：

- 后端完成，前端只剩占位
- 页面可打开，但页面子功能未迁
- 只有主链，缺少管理能力
- 只有显性 API，缺少测试已固化的隐性语义

## 5. 阶段总览

| Phase | 名称 | 核心产物 |
|---|---|---|
| 0 | 基线冻结 | 覆盖矩阵、字段映射、测试语义矩阵 |
| 1 | 新栈底座 | monorepo、contracts、infra、settings、compose |
| 2 | 迁移底座 | schema、artifact registry、导入器、校验器 |
| 3 | 后端并行重建 | bounded context、workflow、projection、API |
| 4 | 前端并行重建 | 八个页面、shared client、event stream、测试 |
| 5 | 总集成与切换 | rehearsal、故障注入、cutover、回滚演练 |

具体并行规则见 `12-Subagent-并行执行协议.md`。

## 6. 切换闸门

只有同时满足以下条件，才允许正式切换：

1. `06` 中所有功能项关闭。
2. `07` 中所有接口与页面承接完成。
3. `08` 中所有字段有去向。
4. `09` 中 P0/P1 回归全部通过。
5. `10` 中隐性语义全部落地并回归。
6. `11` 中 graph 全链路完成，不再是空白依赖。
7. `13` 与 `14` 的前后端交付物全部完成。
8. 已完成一次真实迁移 rehearsal。
9. 已完成一次真实故障演练。
10. 已完成一次真实回滚演练。

缺任一项，都不能声称“100% 完成”。
