# 06-全功能盘点与迁移对照矩阵

## 1. 目标

本文件用于把“现有项目全部功能”收口为可执行迁移矩阵，避免只迁主链、不迁边角功能。

判断标准只有一个：

- 旧系统中只要存在用户可见能力、API 能力、后台任务能力、数据维护能力、LLM 设施能力、运行时观测能力，就必须在本矩阵中出现。

未出现在本矩阵中的功能，一律视为“未被覆盖”，不允许宣布迁移完成。

---

## 2. 覆盖基线

本矩阵的覆盖源来自三处真实代码：

1. 后端 Flask API：
   - `backend/app/api/*.py`
2. 前端路由与工作台：
   - `frontend/src/router/index.js`
   - `frontend/src/views/**`
   - `frontend/src/api/*.js`
3. 现有自动化测试：
   - `backend/tests/test_*.py`

因此，这份矩阵不是“产品理想清单”，而是“代码当前已经存在的功能全集”。

注意：

- 本文件覆盖的是显性功能全集。
- 对于测试已固化但不容易从页面/API 直接看出的底层行为语义，必须同时查看 `10-隐性语义与底层兼容矩阵.md`。
- 对于 graph 链路，必须同时查看 `11-Graph-重构路径与验收方案.md`。

## 7. 完整迁移的强制判定规则

只有同时满足以下 8 条，才允许宣称“所有功能已完整迁移”：

1. 本文档列出的全部旧 API 均有新实现或兼容实现。
2. 八个前端路由页面都已在新技术栈可用。
3. 页面内部子功能没有被静默删除。
4. P0 测试能力全部被新测试矩阵覆盖。
5. 所有后台管理能力，包括 `reindex`、`reviewer rules`、`llm activity` 等都已承接。
6. 所有已废弃接口的兼容语义也被保留，例如 worldline 的 `410` 响应。
7. 旧 JSON/SQLite 中不存在“无人承接的数据源”。
8. 迁移状态矩阵中不存在 `TBD / unknown / not planned` 项。
9. `10-隐性语义与底层兼容矩阵.md` 中不存在未承接行为。
10. `11-Graph-重构路径与验收方案.md` 中 graph 链路已关闭。

- `迁移阶段`
