# 14-后端完整重构方案

## 1. 目标

本文件定义新后端的完整重构方案。目标是将当前 `Flask + services + JSON/SQLite/文件系统 + 线程任务` 重建为可持续演进的模块化单体。

技术栈固定为：

- `FastAPI`
- `Pydantic`
- `SQLAlchemy 2`
- `Alembic`
- `PostgreSQL`
- `MinIO`
- `Redis`
- `Temporal`

---

## 2. 后端目录结构

```text
apps/api/src/
  bootstrap/
  interfaces/http/
  interfaces/events/
  modules/
  shared/
```

固定约束：

- `interfaces/http` 只做路由和 DTO 映射
- `modules/<context>/application` 只处理命令和查询编排
- `modules/<context>/domain` 不依赖框架
- `modules/<context>/infrastructure` 实现 repository / storage / adapter
- workflow activity 不直接持有 web 层依赖

## 4. API 与工作流设计

### 4.1 API 原则

- 新接口统一 `/api/v2`
- 命令和查询分离
- 长任务统一建模为 operation/workflow
- 错误使用稳定 `code/message/details/retryable`

### 4.2 必须 workflow 化的链路

- seed extraction
- graph build
- worldline prepare
- worldline auto-evolve
- draft generate
- draft revise
- model sync

### 4.3 不允许的实现

- API 直接拉本地线程
- service 直接读写散落 JSON 作为主事实
- worker 静默 fallback 成“成功”

---

## 5. 数据层

### 5.1 PostgreSQL

必须承接：

- projects
- manuscripts
- artifacts metadata
- workflow runs / steps
- entities / relationships
- archives / memories / memory events
- worldline sessions / world states / timeline events
- session agents / actions / dialogues
- draft runs / revisions / reviews / finalized chapters
- llm providers / channels / models / bindings

### 5.2 MinIO

必须承接：

- 原始上传文件
- extracted_text
- seed / graph / context / draft / review 等大制品

### 5.3 Redis

只承担：

- locks
- dedupe keys
- hot cache
- event fanout

### 5.4 Temporal

必须负责 durable execution，而不是只做通知壳。

---

## 6. 迁移与回滚

- 旧数据全部先原样归档再结构化导入
- 正式切换前必须做迁移 rehearsal
- 正式切换后若失败，只能回滚到切换前快照，不做在线双向同步

---

## 8. 后端并行拆分建议

推荐拆为 5 条 lane：

- BE-A：`contracts + shared kernel + bootstrap`
- BE-B：`migration + schema + artifact registry`
- BE-C：`project + seed-analysis + graph`
- BE-D：`archive-library + llm-facility`
- BE-E：`worldline + writer`

其中：

- `writer` 不得早于 `worldline` 的稳定查询层
- `worldline` 不得早于 `graph + archive`

---

## 9. 完成判定

后端完成必须同时满足：

1. 所有当前仓库接口有新实现。
2. 所有当前仓库数据源有新去向。
3. 所有必须 workflow 化的链路已脱离旧线程任务。
4. graph/worldline/writer 三条复杂链均有 durable state。
5. 迁移 rehearsal、故障演练、回滚演练全部通过。
