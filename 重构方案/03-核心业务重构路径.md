# 核心业务重构路径
## 范围
只覆盖 3 条主链：`小说上传 -> seed extract -> analysis/artifacts`、`worldline prepare -> session start -> step/auto-evolve`、`writer chapter context -> draft generate/revise/finalize`。
目标架构统一采用 `command + workflow + domain + projection + api`，并一次性消除 4 个结构病灶：本地线程任务、SSE 直连 orchestrator、文件系统/SQLite 混合持久化、单世界但残留 branch 语义。

## 统一重写原则
- API 只收命令、查投影，不直接承载长流程执行。
- 长流程统一进入 durable workflow，不再依赖 Flask 进程内线程。
- 主事实源统一入库；原稿、长文本、原始快照只进对象存储。
- worldline 改成显式 `current_world` 模型，彻底删除 `branch_count / branches[] / branch_id=main`。

## 1. 小说上传 -> Seed Extract -> Analysis / Artifacts
### 旧代码如何运转
关键模块：接口 `backend/app/api/project.py` 的 `POST /api/project/seed/extract`；项目持久化 `backend/app/models/project.py` 的 `ProjectManager`；任务入口 `backend/app/services/seed_extract_task_service.py`；主流程执行 `backend/app/services/seed_extract_runner.py`；任务状态 `backend/app/models/task.py`。

旧链路时序：
```text
POST /api/project/seed/extract
  -> ProjectManager.create_project()
  -> ProjectManager.save_file_to_project()
  -> SeedExtractTaskService.create_task()
      -> TaskManager.create_task("seed_extract")
      -> project.status = SEED_PROCESSING
      -> Thread(target=_run_worker).start()
  -> 返回 202 + task_id

后台线程 _run_worker
  -> SeedExtractRunner.run()
      -> _extract_documents / _save_text
      -> segment_documents
      -> build skeleton_timeline / analysis_blocks / anchor_points
      -> extract local_block_facts / merge story_memory / entity_resolution
      -> contextual_block_analysis
      -> generate chapter_cards / continuity / seed_analysis / ontology
      -> ProjectManager.save_project_json(...多份产物)
      -> project.status = ONTOLOGY_GENERATED
      -> TaskManager.update_task(COMPLETED)
```

当前持久化：项目元数据在 `uploads/projects/<project_id>/project.json`；原稿在 `files/*`；正文抽取在 `extracted_text.txt`；阶段产物散落为 `chapter_segments.json`、`story_memory.json`、`seed_analysis.json`、`ontology` 等；任务状态单独在 `task_runs` SQLite。状态变迁是 `CREATED -> SEED_PROCESSING -> ONTOLOGY_GENERATED | FAILED`。

旧实现伪代码：
```python
def extract_story_seed(req):
    project = ProjectManager.create_project()
    save_uploads(project, req.files)
    task_id = SeedExtractTaskService().create_task(project_id=project.id, ...)
    return Accepted(task_id)

def create_task(...):
    task_id = TaskManager().create_task("seed_extract")
    project.status = SEED_PROCESSING
    Thread(target=_run_worker, daemon=True).start()
```

结构性问题：
- 线程任务不 durable，进程重启后只能靠 `recover_missing_task()` 补失败态。
- `ProjectManager.save_project_json()` 让“产物文件集合”承担事实源职责。
- 项目状态与任务状态分离，缺乏统一的作业审计链。
- 章节、事件、记忆、ontology 都是副产物文件，不是稳定的领域对象。

### 新架构下如何重写
分层设计：
- Command：`CreateStoryProject`、`UploadManuscript`、`StartSeedExtraction`、`RetrySeedExtraction`
- Workflow：`SeedExtractionWorkflow`
- Domain：`StoryProject`、`Manuscript`、`SeedExtractionJob`、`SeedArtifactSet`
- Projection：`project_overview_view`、`seed_job_status_view`、`seed_artifact_catalog_view`、`chapter_segment_view`
- API：`POST /api/projects`、`POST /api/projects/{id}/manuscripts`、`POST /api/projects/{id}/seed-jobs`、`GET /api/seed-jobs/{job_id}`

建议把 `SeedExtractRunner` 拆成可审计步骤：`ingest_manuscript`、`extract_text`、`segment_chapters`、`build_story_memory`、`generate_seed_analysis`、`generate_ontology`、`publish_seed_artifacts`。

新实现伪代码：
```python
def start_seed_job(project_id, cmd):
    job_id = command_bus.handle(StartSeedExtraction(project_id=project_id, ...))
    return Accepted(job_id)

@workflow.defn
class SeedExtractionWorkflow:
    async def run(self, cmd):
        manuscript = await ingest_manuscript(cmd)
        text = await extract_text(manuscript)
        segments = await segment_chapters(text)
        memory = await build_story_memory(segments)
        analysis = await generate_seed_analysis(memory, cmd.analysis_goal)
        ontology = await generate_ontology(analysis, memory)
        await publish_seed_artifacts(project_id=cmd.project_id, ...)
```

重写收益：
- 本地线程消失，seed 主链变成可恢复、可重试、可回放的 workflow。
- 文件系统/SQLite 混合主状态消失，主事实统一入库，大文本和快照转对象存储。
- 前端查询 `seed_job_status_view`，不再轮询“线程是否还活着”。
- 章节、事件、记忆、ontology 变成版本化领域产物，可被 archive、worldline、writer 直接消费。

可拆任务：先建 `StoryProject / SeedExtractionJob` schema，再把 `SeedExtractRunner` 活动化，最后为现有 JSON 产物建立 projection。

## 2. Worldline Prepare -> Session Start -> Step / Auto-Evolve
### 旧代码如何运转
关键模块：prepare 接口 `backend/app/api/worldline_prepare.py`；prepare 服务 `backend/app/services/worldline_prepare_service.py`；session/step 接口 `backend/app/api/worldline_session.py`；引擎 `backend/app/services/worldline_engine.py`；单世界约束 `backend/app/services/worldline_single_world.py`；session 存储 `backend/app/services/world_state_store.py`；runtime `backend/app/services/worldline_runtime_service.py`；auto-evolve `backend/app/services/worldline_auto_evolution_task_service.py`。

旧链路时序：
```text
POST /api/worldline/session/prepare
  -> WorldlinePrepareService.start_prepare()
      -> TaskManager.create_task("worldline_prepare")
      -> WorldlinePrepareStorage.save_run(...)
      -> Thread(target=_run_prepare).start()

_run_prepare()
  -> _prepare_branch()
  -> registry.list_agents(branch)
  -> LLM 物化 dossiers
  -> save run + events + dossiers

POST /api/worldline/session/prepare/{prepare_id}/start
  -> build_branches(run["branch_count"])  # 实际固定 1
  -> WorldlineSession(branches=[...])
  -> store.save_session(session.json)
  -> runtime_service.ensure_session_runtime(runtime sqlite)

POST /api/worldline/session/{session_id}/step
  -> worldline_engine.step()
      -> branch_service.advance_branch()
      -> runtime_service.record_step()
      -> store.save_session(session.json)

POST /api/worldline/session/{session_id}/auto-evolve
  -> TaskManager.create_task("worldline_auto_evolution")
  -> Thread(target=_run_worker).start()
  -> queue_action()
  -> step(event_status="candidate")
```

当前模型和持久化冲突非常明显：`backend/app/models/worldline.py` 仍保留 `branch_count + branches[]`；`worldline_engine._branch_count()` 却直接返回 `1`；`worldline_single_world.resolve_branch_id()` 又只允许 `main`。会话主状态在 `worldlines/sessions/<session_id>/session.json` 和 `worldlines/index.json`，runtime 再落独立 SQLite，保存 `agent_registry / action_log / dialogue_log / relation_log / snapshots`。

旧实现伪代码：
```python
def create_session(...):
    source = source_loader.load(...)
    branches = branch_service.build_branches(branch_total=1, ...)
    session = WorldlineSession(branch_count=len(branches), branches=branches)
    store.save_session(session)
    runtime_service.ensure_session_runtime(session)

def step(...):
    session = store.load_session(session_id)
    branch = current_world(session)
    step_result = branch_service.advance_branch(branch, session, ...)
    runtime_service.record_step(step_result)
    store.save_session(session)
```

结构性问题：
- 单世界业务事实与多分支数据模型打架，API 和前端都被迫携带伪 branch 参数。
- `session.json` 与 runtime SQLite 双写，状态一致性依赖调用顺序。
- prepare 和 auto-evolve 仍是线程任务，没有 durable lifecycle。
- `step()`、`queue_action()`、`prepare()` 都在直接操纵存储，没有命令日志与事件日志分离。

### 新架构下如何重写
分层设计：
- Command：`PrepareWorldline`、`StartWorldlineSession`、`QueueAgentAction`、`AdvanceCurrentWorld`、`AutoEvolveCurrentWorld`、`InjectWorldVariable`
- Workflow：`WorldlinePrepareWorkflow`、`WorldlineAutoEvolveWorkflow`
- Domain：`WorldlineSession`、`CurrentWorld`、`PreparedAgentDossier`、`WorldEvent`、`AgentAction`
- Projection：`worldline_prepare_status_view`、`worldline_session_view`、`worldline_timeline_view`、`worldline_agent_console_view`
- API：`POST /api/worldlines/preparations`、`POST /api/worldlines/preparations/{id}/start`、`POST /api/worldlines/sessions/{id}/commands/advance`、`GET /api/worldlines/sessions/{id}/timeline`

单世界必须体现在模型层：`WorldlineSession` 只保留 `current_world`，不再保留 `branches[]`、`branch_count`、`branch_id` 兼容字段；timeline、agent roster、candidate events 都从 `current_world` 事件流投影出来。

新实现伪代码：
```python
def prepare_worldline(cmd):
    prepare_id = command_bus.handle(PrepareWorldline(...))
    return Accepted(prepare_id)

@workflow.defn
class WorldlinePrepareWorkflow:
    async def run(self, cmd):
        source = await load_world_source(cmd)
        dossiers = await materialize_agent_dossiers(source)
        snapshot = await compose_initial_world_snapshot(source, dossiers)
        return WorldlinePrepared(snapshot_id=snapshot.id)

def advance_current_world(cmd):
    events = worldline_domain.advance(session_id=cmd.session_id, ...)
    projection_updater.apply(events)
```

重写收益：
- `branch_count / branches[] / branch_id=main` 彻底删除，单世界语义终于和代码一致。
- session 与 runtime 双写消失，命令侧只写统一事实存储，projection 负责查询展开。
- prepare / auto-evolve 改成 workflow，可恢复、可取消、可重放。
- 前端不再传 branch 兼容参数，工作台天然围绕当前世界组织。

可拆任务：先删 branch 壳，再把 `record_step()` 改为领域事件输出，最后把 prepare 和 auto-evolve 提升为 workflow。

## 3. Writer Chapter Context -> Draft Generate / Revise / Finalize
### 旧代码如何运转
关键模块：context 接口 `backend/app/api/novel.py` 的 `POST /api/novel/chapter-context`；context builder `backend/app/services/chapter_context_pack_builder.py`；draft SSE `POST /api/novel/draft/generate`、`POST /api/novel/draft/revise`；编排器 `backend/app/services/draft_agents/orchestrator.py`；子 Agent `context_agent.py`、`memory_agent.py`、`style_agent.py`、`writer_agent.py`、`reviewer_agent.py`；finalize `POST /api/novel/draft/finalize`。

旧链路时序：
```text
POST /api/novel/chapter-context
  -> ChapterContextPackBuilder.build(payload)
      -> _build_project() 或 _build_worldline()
      -> 读取 project JSON + worldline runtime + canon history
      -> 输出 pack + writer_prompt_block

POST /api/novel/draft/generate  (SSE)
  -> NovelDraftOrchestrator.generate_stream(payload)
      -> ContextAgent.collect()
      -> MemoryAgent.collect()
      -> StyleAgent.analyze()
      -> WriterAgent.generate_stream()
      -> ReviewerAgent.review()
      -> SSE 推 text_chunk / done

POST /api/novel/draft/revise  (SSE)
  -> 前端回传 previous_text + context_pack_snapshot + memory_bundle_snapshot + style_hints_snapshot
  -> Orchestrator.revise_stream()

POST /api/novel/draft/finalize
  -> 回写 chapter_cards.json / chapter_continuity.json / chapter_segments.json
  -> ChapterMetaService.replace_project_chapter_cards(...)
```

当前状态与耦合：
- `ChapterContextPack` 只是临时 JSON，不是服务端持久化对象。
- draft 没有 `DraftSession / DraftRevision`，修订依赖前端回传快照。
- `ChapterContextPackBuilder` 横跨 project canon、worldline runtime、history recall。
- `MemoryAgent`、`StyleAgent`、`ReviewerAgent` 中存在跳过 / 默认值 / 审校跳过路径。

旧实现伪代码：
```python
def draft_generate():
    orchestrator = NovelDraftOrchestrator()
    return SSE(orchestrator.generate_stream(request.json))

def generate_stream(payload):
    context_pack = context_agent.collect(payload)
    memory_bundle = memory_agent.collect(...)
    style_hints = style_agent.analyze(...)
    for chunk in writer_agent.generate_stream(...):
        yield text_chunk(chunk)
    review = reviewer_agent.review(...)
    yield done(full_text, review)
```

结构性问题：
- SSE 连接本身承载多 Agent 编排生命周期，HTTP 断开会让业务执行边界变形。
- 失败语义不干净，默认风格、空记忆、审校跳过会遮蔽真实问题。
- revise 依赖客户端保存快照，服务端不掌握完整草稿状态。
- finalize 直接回写散落 JSON，不是对 `CanonChapter` 的一致性提交。

### 新架构下如何重写
分层设计：
- Command：`BuildChapterContext`、`StartDraftWorkflow`、`SubmitDraftRevision`、`FinalizeDraftAsCanon`
- Workflow：`DraftGenerationWorkflow`
- Domain：`DraftSession`、`DraftRevision`、`ChapterContextPack`、`CanonChapter`
- Projection：`chapter_context_view`、`draft_session_status_view`、`draft_revision_view`、`writer_workbench_view`
- API：`POST /api/writer/context-jobs`、`POST /api/writer/drafts`、`POST /api/writer/drafts/{id}/revisions`、`POST /api/writer/drafts/{id}/finalize`

建议把旧 orchestrator 五段式流程改成服务端持久化步骤：`build_context_pack`、`resolve_pov_memory`、`resolve_style_profile`、`generate_draft`、`review_draft`。SSE/WebSocket 只订阅 `draft_session_status_view`，不再直接承载执行本体。

新实现伪代码：
```python
def start_draft(cmd):
    draft_id = command_bus.handle(StartDraftWorkflow(...))
    return Accepted(draft_id)

@workflow.defn
class DraftGenerationWorkflow:
    async def run(self, cmd):
        context_pack = await build_context_pack(cmd.scope)
        memory = await resolve_pov_memory(cmd.scope, cmd.pov)
        style = await resolve_style_profile(cmd.project_id, cmd.chapter_id)
        text = await generate_draft(context_pack, memory, style, cmd.author_instruction)
        review = await review_draft(text, context_pack, memory)
        return DraftRevisionProduced(text=text, review=review)

def stream_draft_events(draft_id):
    return subscribe_projection("draft_session_status_view", draft_id)
```

重写收益：
- SSE 不再直连 `NovelDraftOrchestrator`；连接只负责订阅事件流。
- context / memory / style / review 全部服务端持久化为 `DraftRevision` 输入快照。
- `ChapterContextPackBuilder` 被拆成 query service：canon query、worldline query、history recall query 分离。
- 失败即失败，不再用默认风格或空记忆掩盖错误。
- finalize 通过 `FinalizeDraftAsCanon` 统一更新章节 canon、连续性和历史召回 projection。

可拆任务：先建 `DraftSession / DraftRevision` 状态机，再把 `NovelDraftOrchestrator` workflow 化，最后把 `ChapterContextPackBuilder` 降为只读查询层。

## 三条主链最大的结构性问题
- 小说上传链：线程驱动流程 + 文件产物即状态。
- worldline 链：单世界业务事实与多分支数据模型相互打架。
- writer 链：HTTP/SSE 连接直接承载多 Agent 编排生命周期。
