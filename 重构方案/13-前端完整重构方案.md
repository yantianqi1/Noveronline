# 13-前端完整重构方案

## 1. 目标

本文件定义新前端的完整重构方案。目标不是简单把 Vue 页面“翻译”成 React，而是在不丢失任何现有页面和子功能的前提下，建立可维护的工作台前端。

技术栈固定为：

- `React 19`
- `TypeScript`
- `Vite`
- `TanStack Query`
- `Zustand`
- `React Router`
- `Tailwind CSS`

---

## 2. 目录结构

```text
apps/web/src/
  app/
  pages/
  features/
  entities/
  shared/
```

固定约束：

- `pages/` 只承接路由容器
- `features/` 承接业务功能块
- `entities/` 承接复用的领域视图
- `shared/` 承接 API client、SSE client、ui、hooks、lib

---

## 4. 共享前端基础设施

### 4.1 API 层

- 统一消费 generated OpenAPI client
- 禁止页面直接手写 URL
- 兼容 SSE 的 event stream client 放在 `shared/api`

### 4.2 状态层

- server state 统一走 TanStack Query
- client state 统一走 Zustand
- 工作台级状态机不能散在组件本地

### 4.3 错误与空态

每个页面必须显式实现：

- loading
- empty
- failed
- retryable failed
- stale data refresh

### 4.4 事件流

以下链路必须使用统一 event client：

- draft generate/revise
- worldline auto-evolve
- graph build
- seed / operation progress

---

## 5. 前端测试策略

- 单元测试：Vitest
- 组件行为：React Testing Library
- 页面主链：Playwright
- API 契约 mock：generated mock 或 MSW

最低必测页面：

- `/`
- `/story-graph`
- `/worldline`
- `/writer`
- `/archive-library`
- `/llm-facility`

---

## 6. 前端并行拆分建议

推荐拆为 3 条前端 lane：

- FE-A：`app shell + overview + guide + archive-library + llm-facility`
- FE-B：`story-graph + worldline + character-console`
- FE-C：`writer`

依赖顺序：

- FE-A 可最早启动
- FE-B 依赖 graph/worldline contracts
- FE-C 依赖 writer/worldline/archive contracts

---

## 7. 完成判定

前端完成必须同时满足：

1. 八个页面全部可访问。
2. 页面子功能无静默删除。
3. 不再依赖 `frontend/src/api/*.js` 旧手写调用面。
4. 所有长流程统一通过 event client 订阅。
5. `/writer` 与 `/worldline` 可独立跑完整链路。
