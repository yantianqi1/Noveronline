# 07-全接口与前端页面覆盖清单

## 1. 目标

本文件不再讨论架构理念，只回答两个问题：

1. 旧系统到底暴露了哪些接口与页面。
2. 新技术栈下这些接口与页面如何一项不漏地被承接。

前端与后端的完整目标结构分别见：

- `13-前端完整重构方案.md`
- `14-后端完整重构方案.md`

## 4. 新前端完整重写要求

## 4.1 不允许只迁页面外壳

以下内容必须一起重写，才算页面迁移完成：

- 页面路由
- 页面布局逻辑
- 页面状态机
- 数据请求与缓存
- SSE/轮询处理
- 错误态与空态
- 关键交互操作

## 4.2 不允许漏掉“非主视觉功能”

这些经常被遗漏，但必须保留：

- `reviewer rules` 编辑
- `step trace` 查看
- `graph build` 轮询
- `archive reindex`
- `llm activity`
- worldline `410` 废弃接口兼容
- worldline variable lock
- guide/workflow 指引

---

## 5. 完整迁移的联调闸门

只有同时满足以下条件，前端/接口层才允许从“兼容”转“正式切主”：

1. 所有旧接口都能在兼容层命中并返回可解析结果。
2. 八个页面全部在新前端可访问。
3. 所有 API client 函数都有 typed client 对应实现。
4. 所有 SSE 端点都已有新 event stream 协议。
5. `/writer` 与 `/worldline` 两个工作台在新前端上可独立完成全链路操作。
6. `archive-library`、`story-graph`、`character-console`、`llm-facility` 均非占位状态。
7. 旧页面下线前已有回切路由。

---

## 6. 本文件的用途

后续任何“功能已经迁完”的说法，都必须先对照本文件逐项勾选。

如果某个页面、接口、client 函数、管理操作没有在这里被标记为“已承接”，那么它就是未迁移功能。
