# 09-功能等价验收与回归测试矩阵

## 1. 目标

本文件用于定义“什么叫完整迁移成功”。

原则非常简单：

- 新架构不是“页面能打开”就算完成。
- 必须证明旧系统已有功能在新系统里行为等价，且能被自动化回归。

本文件默认与以下文档共同生效：

- `10-隐性语义与底层兼容矩阵.md`
- `11-Graph-重构路径与验收方案.md`

---

## 2. 验收层级

完整迁移验收分为 5 层：

1. 数据等价
2. API 等价
3. 页面/交互等价
4. 工作流可恢复性等价
5. 回滚可用性等价

只有 5 层都通过，才能宣称“所有功能已完整迁移”。

## 7. 回归执行顺序

完整回归必须按顺序执行：

1. 数据迁移 dry-run 校验
2. 数据 checksum 对账
3. API 契约回归
4. 主链 integration 回归
5. 前端 e2e 回归
6. 故障注入回归：
   - worker 重启
   - 对象存储短暂不可用
   - LLM 超时
   - SSE 中断
7. 回滚演练

如果第 1 到第 7 中任意一步失败，本次迁移不得进入切流量阶段。

---

## 8. 功能等价的严格定义

以下任一情况都算“未完整迁移”：

1. 旧接口存在但没有兼容实现。
2. 旧页面存在但新前端只给占位页。
3. 旧功能依赖的后台管理能力缺失，例如 reindex、reviewer rules、llm activity。
4. 旧数据有字段无人承接。
5. 旧测试已有语义，新系统没有对应回归。
6. worker 或 API 重启后 draft/worldline/seed 无法恢复。
7. 回滚后无法恢复旧主链。

---

## 9. 迁移完成的最终闸门

只有同时满足以下条件，才允许在项目级别标记“全部功能已完成新技术栈重写”：

1. `06-全功能盘点与迁移对照矩阵.md` 中所有项均已关闭。
2. `07-全接口与前端页面覆盖清单.md` 中所有接口和页面都有承接实现。
3. `08-旧数据逐字段映射与迁移脚本规范.md` 中所有旧字段都有去向。
4. 本文档中的 P0/P1 回归全部通过。
5. `10-隐性语义与底层兼容矩阵.md` 中所有行为已有对应回归。
6. `11-Graph-重构路径与验收方案.md` 中 graph 专项回归通过。
7. 已完成一次真实回滚演练并验证成功。

缺少任一项，都不能声称“所有功能全部完整迁移”。
